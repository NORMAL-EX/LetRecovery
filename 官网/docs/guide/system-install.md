# 系统安装

**系统安装**页用于把 Windows 镜像部署到某个分区。

## 支持的镜像格式

| 格式 | 说明 |
| --- | --- |
| **WIM / ESD / SWM** | 标准 Windows 镜像，经 wimlib 释放。SWM 的全部连续分卷会作为一套源被锁定和校验。 |
| **GHO / GHS** | Ghost 单文件或连续分卷，经内置 Ghost 引擎还原；全部 GHS 分卷必须完整。 |
| **ISO** | 自动挂载，使用其中的 `install.wim` / `install.esd` / `install.swm`。 |
| **XP / 2003 i386** | 原版 XP/2003 安装盘（根目录是 `\I386`、没有 `install.wim`）会被识别为文本模式安装介质，详见 [Windows XP / 2003 安装](/guide/xp-install)。 |

选好镜像后，选择要安装的**版本**（镜像索引）。版本下拉里会自动过滤掉不可安装的卷（如 WindowsPE / Setup 介质卷），默认选中第一个可安装版本。

直接模式与经 PE 模式都支持完整的 SWM/GHS 分卷集合。正常端会从已持有的原文件句柄逐一复制所有连续分卷到受保护的随机会话目录，并把每个文件的顺序、长度和 SHA-256 写入受认证清单；PE 端重新严格枚举并拒绝缺失、额外、乱序或不连续分卷，不会只凭首卷路径在公开目录重新发现文件。

## 选择目标分区

在列表里选目标分区。表格会显示容量、可用空间、卷标、分区表（GPT/MBR）、BitLocker状态，以及该分区是否已有系统。

经 PE 安装时，正常系统端会在所选卷写入本次随机标记；重启后只寻找内容与本次认证配置完全一致的唯一标记。其它分区上同名但内容不同、损坏或打不开的文件会直接忽略，不会导致安装失败；跨重启找目标不依赖缓存的磁盘号、分区号、容量、卷标或整盘布局。

若需要自动准备数据分区，容量固定按“实际会复制的镜像全部分卷、在线 OEM 驱动、PCA、版本化用户驱动和 UefiSeven 文件总大小 + 2 GiB”计算。驱动大小直接通过 Windows SetupAPI 定位现有 Driver Store 包并读取元数据，不会为了统计先复制一份，也不会再按镜像百分比或固定 8–12 GiB 粗略猜测。

## 分区重装、全盘重装与双系统

- **普通分区重装**只处理列表中选择的目标分区。
- **全盘重装**会在正常 Windows 中列出本次计划清空的全部电脑内置硬盘，并要求最后一次明确确认。被列出的硬盘上现有 Windows、分区和个人文件都会删除；同盘暂存卷会保留到镜像、驱动、配置和引导都完成后才尝试回收，回收失败只报告安装完成带警告。
- **创建双系统**由正常 Windows 精确缩小用户选择的源卷，并在同一次事务中预创建新 Windows 卷；若没有其它空间足够的数据卷，同一次缩卷还会创建一个最低容量为“实际安装文件总量 + 2 GiB”的数据卷。WinPE 只使用本次随机标记匹配的预创建卷，不会再次缩卷或猜测重建目标。写盘前失败会删除本次预创建卷并把源卷扩回；一旦删除、格式化或镜像写入开始，就不会伪装成已经恢复旧系统。

全盘与双系统流程目前已经通过代码检查和非破坏性模拟测试；仍需在可丢弃虚拟机中验证 GPT/MBR、同盘暂存、非整 MiB provider extent 和双系统启动菜单，不能据此视为实体磁盘验证已完成。

::: tip 目标盘被 BitLocker 加密了？
若目标分区处于锁定状态，安装前会要求先解锁；但“已解锁”不等于跨重启仍可用。当前受认证的**经 PE 安装**不会透传恢复密钥，目标必须在交接前彻底解密为 NotEncrypted，否则失败关闭——详见
[BitLocker 加密盘重装](/guide/bitlocker)。
:::

## 安装方式

LetRecovery 会自动决定怎么装：

- **直接模式**——目标**不是**正在运行的系统盘，或 LetRecovery **本来就在 WinPE 里** 运行时。直接格式化分区并释放镜像。
- **经 PE 模式**——从桌面把系统装到**正在运行的系统盘**时。LetRecovery 在 Windows API 返回的实际系统卷创建临时 WinPE 引导载荷并重启进入，再由 [PE 端](/guide/what-is-letrecovery#工作原理)格式化目标系统卷并释放镜像；系统卷不要求是 `C:`。运行中的系统无法覆盖自身，所以要重启。

若上次任务因断电或异常退出留下 `LetRecovery_PE` 文件，下一次任务会先回滚其可信启动事务，再只清理 LetRecovery 精确命名的普通文件。未知文件、目录和链接不会被递归删除，也不会因为与产品目录同名就被当成产品数据。

## 部署前镜像校验

直接模式和**经 PE 模式**都会在格式化目标盘**之前**校验并锁定整套安装源（WIM/ESD/SWM 经 wimlib）。坏镜像或变化、缺失、额外的分卷会在**动盘之前**被拦下。

::: warning GHO/GHS 的校验范围不同
- GHO 镜像只做头/尾结构性检查，不走 wimlib 校验。
- GHS 分卷的完整集合、顺序、长度与 SHA-256 会被绑定，但 Ghost 自有格式的内部语义仍由 Ghost 引擎处理。
:::

## 新装镜像与已有账户的判定

无人值守、账户修改、预装软件和首次登录任务只会应用到能够确认是全新安装模板的 Windows 镜像。PE 会以只读应用配置单元方式实际打开离线 `SAM`，核对 RID 记录与名称索引，并结合 Windows Setup 的镜像状态判断：只有处于 OOBE 重封装状态、SAM 读取成功且没有真实用户账户时才按全新镜像处理。

Administrator、Guest、DefaultAccount、defaultuser0、WDAGUtilityAccount 等 Windows 内置或安装阶段账户不会被误当成用户；RID 1000 及以上且不属于这组精确系统名称的账户会被视为真实用户。已捕获/备份镜像、已完成安装的镜像、存在真实用户的镜像，或 SAM 无法读取/两套索引不一致时，都会保留原账户与密码并跳过可能覆盖用户状态的选项，不会仅凭 `ImageState` 猜成全新系统。

## 失败与自动回退

在原系统仍完整、目标分区尚未开始删除或格式化、镜像也尚未开始写入时，安装前检查失败会自动清理本次 PE 启动项、认证配置和能够安全确认的临时分区。格式化/删除一旦开始，或未格式化安装已经把目标交给镜像引擎，就进入不可逆阶段；此后失败不会尝试拼回旧系统或旧引导，也不会声称已经回退，只会保留诊断并要求重新安装或人工恢复。

核心安装已经完成但临时分区回收、可选驱动或其它非承重步骤失败时，结果会显示为“安装完成，但有警告”。交互式 PE 会停留在警告页等待用户阅读和处理，不会因为普通自动重启选项而数秒后关机；只有明确启用的无人值守自动化终态才会按配置关机或重启。

## 引导模式

LetRecovery 会自动识别 UEFI / Legacy（GPT→UEFI、MBR→Legacy）并写入对应引导文件。需要时也可在**引导模式**下拉框里手动指定 `自动 / UEFI / Legacy`。该下拉框始终可见；启用无人值守时它与"自定义无人值守"按钮并列同一行，否则单独成行。

对支持的 Windows 10/11 和 Server 2016+ UEFI 镜像，程序还会在写盘前检查 Secure Boot 的 PCA2011/PCA2023 信任代际，并在旧镜像缺少 BootEx 时使用随包离线资源补齐。通常保持**自动**即可，完整判断和旧系统限制见 [Secure Boot 与 PCA2011 / PCA2023](/guide/secure-boot-pca)。

## 驱动与选项

开始前可在[高级选项](/guide/advanced-options)里启用驱动导出/导入、磁盘控制器驱动注入、无人值守、注册表优化、WiFi 配置迁移等。Windows 7 的 USB3/NVMe/UEFI 资源由最终安装意图按镜像、架构和硬件自动选择，只保留受限的 0xA5 手工兼容尝试；XP/2003 仍显示自己的专用选项。

“预装软件”窗口首次打开时，会只读检测当前所选目标 Windows 的机器级已安装软件，并默认勾选“检测结果与当前服务器软件目录的交集”。匹配采用精确产品名或明确的版本/架构后缀，不使用容易误选的包含匹配；服务器目录不存在的本机软件不会显示，用户手动取消或清空后也不会再次自动勾选。

## 生成自动化配置

在“关于”页打开“显示自动化配置导出（高级）”后，安装页左下方会显示“生成自动化”。它会把当前目标、镜像卷、安装模式、驱动、无人值守、软件和高级选项写成 `cli\install.json`，并生成 `cli\run-install.cmd`；生成过程不会开始安装。请先检查 JSON，再以管理员身份运行 CMD。磁盘编号和已挂载 ISO 内部路径只适用于当前硬件与当前挂载会话，环境变化后应重新生成。密码和 Wi-Fi profile 所在 JSON 使用受保护 ACL，CLI 输出会脱敏，但仍应像凭据文件一样妥善保管。

::: danger
普通重装会**格式化目标分区**；全盘重装会清空确认框中列出的内部硬盘。请先备份。
:::
