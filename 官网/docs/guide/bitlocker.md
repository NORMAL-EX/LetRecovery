# BitLocker 加密盘重装

重装被 **BitLocker** 保护的系统盘，在 WinPE 下通常会失败——加密卷重启后可能重新锁定。安装和备份交接不会把恢复密钥写进公开配置；工具箱中默认关闭的 PE 维护入口则使用独立的受认证私有载荷，不能被安装或备份任务复用。

## 它如何决策

当前生产边界要求经 PE 安装的目标在交接前达到 **NotEncrypted**：

- 目标已解锁且允许安全解密时，正常端会启动并等待**彻底解密**，完成后再创建交接。
- 目标仍锁定、正在加密/解密、状态未知，或在交接时仍为加密卷时，任务会失败关闭，不会依靠盘符扫描或公开配置中的恢复密钥继续。
- 备份 ViaPE 同样要求源卷和目标卷都明确为 NotEncrypted；不会读取或落盘恢复密钥。

启用 `config.json` 的 `pe_maintenance_entry_enabled` 后，正常系统工具箱会显示 **进入 PE 维护环境**。正常端仅 best-effort 收集系统当前可导出的 48 位数字恢复密码，将严格规范化、去重后的有限集合放进本次 LRPE4 私有 boot artifact；公开 config/manifest 只有长度和 SHA-256。PE 认证本次任务后，只对当前仍锁定的有盘符卷逐一尝试 `unlock`。某个卷没有恢复密码、密码不匹配或状态查询失败都不会阻止进入维护桌面。

这条维护路径不会调用 `manage-bde -off`、删除或挂起保护器，也不会开始整盘解密。恢复密码集合不携带盘符、卷标、容量、磁盘号或跨启动指纹；错误内容、旧会话文件和未认证载荷不会被接受。安装与 ViaPE 备份的 NotEncrypted 边界保持不变。新装好的系统默认不继承旧卷的 BitLocker 状态，需要时请在安装完成后重新开启。

## 解锁 ≠ 解密

**解锁**只让当前启动会话可以读取加密卷，重启后可能再次锁定；**解密**会移除卷上的 BitLocker 加密。正因为两者不同，当前 ViaPE 生产路径不会把“在线系统里已解锁”当作跨重启授权。

## 手动管理 BitLocker

[工具箱](/guide/toolbox)里有 **BitLocker 管理**：

- **解锁**（密码 / 恢复密钥）、**解密**整盘；
- **挂起 / 恢复**保护——挂起后密钥以明文留存、重启仍有效，常用于改 BIOS/固件前临时关闭，之后再恢复，**无需**重新加密整盘；
- **查看恢复密钥**。

::: tip Secure Boot 与随包 PE
LetRecovery 通过目标机自带的 **Windows 启动管理器（bootmgfw）** 引导 WinPE，而非自带引导器，因此在开启 Secure Boot 的机器上也能用。
:::
