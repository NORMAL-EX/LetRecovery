# LetRecovery 正常系统端命令行

公开命令行只属于正常系统端 `LetRecovery.exe`。PE 不提供用户命令行：旧 `/PEINSTALL`、`/PEBACKUP` 已停用并固定拒绝；`/AUTO` 只供正常系统端创建并认证的内部跨重启任务启动原生进度界面，不能由外部脚本直接构造或调用。

## 从图形界面生成

“关于”页提供默认关闭的“显示自动化配置导出（高级）”。启用后，系统安装/系统备份页最左侧出现“生成自动化”：安装生成 `cli\install.json` 与 `cli\run-install.cmd`，备份生成 `cli\backup.json` 与 `cli\run-backup.cmd`。生成只读取当前界面状态并写文件，不执行磁盘操作。JSON 经过同一严格 schema 归一化、protected ACL 发布和回读；CMD 使用自身目录相对定位 EXE/JSON，并保留进程退出码。磁盘号和已挂载 ISO 内部路径是当前会话事实，硬件或挂载状态变化后必须重新生成。

## 命令

```text
inspect disks
inspect image --path <image>
inspect pe-cache
install plan --config <file>
install run --config <file> [--yes] [--dry-run]
backup plan --config <file>
backup run --config <file> [--yes] [--dry-run]
update restore
config generate --operation install|backup --output <file> [选项] [--interactive] [--force]
config validate --config <file>
config normalize --config <file> [--output <file>] [--force]
config show --config <file>
```

`disable_windows_update` 只使用可逆策略和服务启动类型：关闭自动更新、移除扫描/下载/安装入口、阻止连接 Windows Update 公网位置，并禁用 `wuauserv`、`UsoSvc`、`WaaSMedicSvc`、`DoSvc`；不会删除服务、任务、文件、ACL，也不改动 BITS 或写入 Defender 的 `DisableAntiSpyware`/`DisableAntiVirus` 旧策略。这会最大程度阻止 Windows Update/Microsoft Update 自动投递 Defender 平台及安全情报更新，但不能保证 Store、Office、手工安装、企业管理或功能升级永远不会重新部署组件。

`update restore` 只恢复 LetRecovery 已验证且仍由本程序拥有的 Windows Update 策略/服务启动类型；它使用安装绑定、逐项所有权和 compare-and-swap 回读，不会覆盖管理员、域策略或 MDM 后续修改。该命令必须从已提权控制台运行，不自动触发 UAC，不弹提示框；部分恢复及冲突写入 stderr JSON Lines 和最终 JSON。

高级优化项也有明确边界：`remove_uwp_apps` 仅对共享固定清单中的精确 AppX 身份撤销 provisioning 和所有用户注册，明确保留新 Outlook、OneDrive Sync 与 Win32 OneDrive；Windows 11 还会在默认用户首次生成前关闭开始菜单推荐和预装内容投递，避免“入门”、纸牌、微软电脑管家等动态入口重新出现。`disable_windows_defender` 深度移除 Defender Antivirus 引擎，并仅尽力移除两个精确 SecHealthUI PFN；SecurityHealthService、Windows Security Center 服务、防火墙、UAC、SmartScreen、VBS 和 Defender for Endpoint 保留。`disable_reserved_storage` 只在已确认 Windows 10/11 build 19041+、使用内置无人值守时调用在线 DISM，失败或最终状态未确认只记 warning。

`inspect disks` 返回 fresh 分区、容量、系统标记、BitLocker 和稳定身份摘要；`inspect image` 返回可安装卷索引、版本、Build 与架构；`inspect pe-cache` 返回逐项实际校验状态。这些命令只读，不需要 `--yes`。

- `plan` 只刷新镜像、分区、BitLocker、目标身份和 PE 缓存状态并生成计划，不执行写盘。
- `run` 必须从已经提权的管理员控制台启动并显式传入 `--yes`；不会弹窗或自动请求 UAC。`--dry-run` 强制只输出计划。
- `run` 复用图形界面相同的 `NativeInstallController`、原生安装/备份 executor 和生产 backend，不生成第二套 PE 配置或危险命令。
- `config generate` 默认非交互；只有显式 `--interactive` 才读取输入，提示本身也是 stderr 上的结构化 JSON Lines，输入提前结束会明确失败。覆盖文件必须 `--force`。
- 配置采用 `schema_version: 1`，拒绝未知字段、JSON 任意层级的重复键和重复命令行参数，避免同一份破坏性配置存在两种解释。配置文件限制为 4 MiB，拒绝重解析点；原子发布前后回读一致，并在最终路径再次核对 protected DACL 仅允许当前交互用户、SYSTEM 和 BUILTIN\Administrators 完全控制，但绝不修改用户所选父目录的 ACL。
- `config show`、最终 JSON 和进度事件始终脱敏内置 Administrator 密码。不要在命令行参数中传递密码；需要时只在受保护配置文件内填写。

旧的 `--install --config <install.json> [--advanced ...]` 已删除，因为它绕过共享规划器并手工拼装 PE 交接。调用会以退出码 2 返回确定的迁移错误，不会静默成功。正常端旧 `/PEINSTALL`、`--pe-install`、`/PEBACKUP`、`--pe-backup` 入口也会在加载配置、请求管理员权限或初始化 GUI 前固定拒绝。

## 配置示例

```json
{
  "schema_version": 1,
  "operation": {
    "type": "install",
    "target_partition": "C:",
    "install_mode": "reinstall_partition",
    "confirmed_disk_numbers": [],
    "image_path": "D:\\Images\\install.wim",
    "volume_index": 1,
    "format_partition": true,
    "repair_boot": true,
    "unattended": true,
    "auto_reboot": false,
    "automation_shutdown_on_terminal": false,
    "driver_action": "auto_import",
    "boot_mode": "auto",
    "boot_pca_mode": "auto",
    "inherit_app_install_prefs": false,
    "preinstalled_software_ids": ["todesk", "7zip-x64", "bandizip-x64"],
    "advanced": {
      "disable_windows_update": true,
      "disable_windows_defender": true,
      "remove_uwp_apps": true
    }
  }
}
```

备份使用 `type: "backup"`，必填 `source_partition`、`save_path`、`name`。版本化意图字段为 `execution_mode`（`auto|direct|via_pe`，默认 `auto`）、`output_policy`（`create|replace|append`，默认 `create`）和 `auto_reboot`（默认 `false`）；它们替代容易被静默忽略的旧 `incremental` 布尔值。正常系统端 CLI 现在放行可在当前系统直接完成的 WIM/ESD `create`、`replace` 和 `append`：`create` 要求目标不存在，后二者要求目标为既有普通文件，并在确认和执行前绑定完整长度与 SHA-256。执行器从拒绝写入/删除共享的同一旧文件句柄复制到私有暂存区；`append` 只修改该副本，`replace` 构造完整新副本，验证完成后才通过 PREPARED journal 和句柄 CAS 发布，失败保留旧目标。`via_pe`、自动重启以及需要 PE 的系统卷备份仍在 plan 阶段以 `unsupported_until_stable_handoff` 失败关闭；PE 端没有公共 CLI。

### schema_version 1 字段

- 安装顶层：`target_partition`、`install_mode`（`reinstall_partition|repartition_all_disks|dual_boot`）、`confirmed_disk_numbers`、`dual_boot_size_gib`、`image_path`、`image_backing_path`、`volume_index`、`format_partition`、`repair_boot`、`unattended`、`auto_reboot`、`automation_shutdown_on_terminal`、`driver_action`（`none|save_only|auto_import`）、`boot_mode`（`auto|uefi|legacy`）、`boot_pca_mode`（`auto|pca2011|pca2023`）、`custom_unattend_path`、`inherit_app_install_prefs`、`preinstalled_software_ids`、`advanced`。默认 `install_mode=reinstall_partition` 且禁止携带磁盘号或双系统容量；`repartition_all_disks` 必须显式列出本次 `inspect disks`/界面展示并由用户确认清空的当前会话磁盘号，`target_partition` 当前所在磁盘必须在其中且是唯一 Windows 盘，其余已确认盘只作为数据盘。`dual_boot` 禁止携带磁盘号，必须提供正整数 `dual_boot_size_gib` 且保持 `repair_boot=true`；该整数 GiB 只表达用户确认的新 Windows 容量，plan 仍用所选镜像的 `TOTALBYTES - HARDLINKBYTES + 2 GiB` 精确预算复核最低值，再复用 GUI 同一个正常端 Shrink、预创建卷、操作后回读和 PE 交接事务。磁盘号只用于正常端从 fresh SetupAPI 库存生成本次随机 locator，不进入 PE 跨启动身份认证。`inherit_app_install_prefs=true` 时必须存在 EXE 相邻的有效 `config.json`，其普通 `install_prefs` 整体覆盖 CLI 中的偏好字段，但目标、镜像、卷索引和破坏性安装模式仍由 CLI 配置决定；继承的旧全盘/双系统计划会被清除。缺失或损坏不能静默变成默认值。`preinstalled_software_ids` 只接受去重的稳定 v4 ID，并在每次 plan 时从在线目录重新解析 URL 和静默命令；目录已成功读取后，ID 找不到、重复、属于 VMware Tools 特殊项或缺少静默命令仍作为确定配置错误停止。若启动初期网络/DNS 暂不可用导致整个可选软件目录在三次重试后仍无法取得，则 plan 输出 `optional_software_catalogue_unavailable` warning、当次不安排这些软件并继续 Windows 核心安装；后续单个或全部软件包下载/安装失败也只汇总 warning。`automation_shutdown_on_terminal=true` 仅用于可丢弃虚拟机自动化：已确认的 normal/PE 终止失败会安排关机；PE 成功仍会启动新系统，受认证首登收尾器逐项尝试全部选定软件后才安排关机，单项软件失败只记 warning。该字段不进入 GUI 偏好，`plan`/`dry-run`/缺少 `--yes` 也不会关机；生成器对应接受 `--automation-shutdown-on-terminal true`。本地安装源支持 WIM、ESD、SWM、GHO、GHS；控制器按目标状态选择 Direct 或受认证 ViaPE。ViaPE 的 SWM/GHS 会把连续全套分卷逐项绑定到 LRHM3，PE 端拒绝 missing/extra/乱序分卷。自定义 unattend 非空时必须同时启用 `unattended`；当前 ViaPE 对自定义 answer 或 Administrator 密码失败关闭，Direct 支持的组合不受此 gate 影响。
- `advanced` 布尔项：`remove_shortcut_arrow`、`restore_classic_context_menu`、`bypass_nro`、`disable_windows_update`、`disable_windows_defender`、`disable_reserved_storage`、`disable_uac`、`disable_device_encryption`、`remove_uwp_apps`、`migrate_wifi`、`install_vmware_tools`、`import_storage_controller_drivers`、`win7_fix_acpi_bsod`、`win7_inject_usb3_driver`、`win7_inject_nvme_driver`、`win7_fix_storage_bsod`、`win7_uefi_patch`、`xp_inject_usb3_driver`、`xp_inject_nvme_driver`。VMware Tools 只允许在明确检测为 VMware 的来宾机中规划；它仍从当前服务器目录唯一解析，不携带旧 URL。Wi-Fi 迁移只由图形界面导出本次捕获的 `wifi_ssid` 与 `wifi_profile_xml`，不接受包含凭据的命令行参数。
- `advanced` 路径/文本项：`wifi_ssid`、`wifi_profile_xml`、`deploy_script_path`、`first_login_script_path`、`custom_drivers_path`、`registry_file_path`、`custom_files_path`、`username`、`volume_label`、`win7_usb3_driver_path`、`win7_nvme_driver_path`；`builtin_administrator` 含 `enabled`、`account_name`、`password`、`auto_logon`。Wi-Fi XML 和密码都会在 `show`/事件中脱敏；任一敏感值非空的 `run` 会再次核对配置文件的精确 protected DACL。
- 备份：`source_partition`、`save_path`、`name`、`description`、`format`（仅 `wim|esd`）、`execution_mode`（`auto|direct|via_pe`）、`output_policy`（`create|replace|append`）、`auto_reboot`。`format` 必须与输出扩展名一致；`execution_mode=direct` 禁止 `auto_reboot=true`。旧 `incremental` 和 SWM 分卷字段仍被严格拒绝。

```json
{"schema_version":1,"operation":{"type":"backup","source_partition":"D:","save_path":"E:\\Backups\\data.wim","name":"Data","description":"Fresh direct backup","format":"wim","execution_mode":"direct","output_policy":"create","auto_reboot":false}}
```

生成安装配置示例：

```bat
LetRecovery.exe config generate --operation install --output D:\lr-install.json --target-partition C: --image-path D:\Images\install.wim --image-backing-path D:\Images\Windows.iso --unattended true --auto-reboot false --builtin-administrator-enabled true --builtin-administrator-account-name Administrator --builtin-administrator-auto-logon true

LetRecovery.exe config generate --operation install --output D:\lr-vm-install.json --target-partition C: --image-path D:\Images\install.wim --inherit-app-install-prefs true --preinstalled-software-ids todesk,7zip-x64,bandizip-x64

LetRecovery.exe config generate --operation install --output D:\lr-full-disk.json --target-partition C: --install-mode repartition_all_disks --confirmed-disk-numbers 0 --image-path D:\Images\install.wim --auto-reboot true

LetRecovery.exe config generate --operation install --output D:\lr-dual-boot.json --target-partition C: --install-mode dual_boot --dual-boot-size-gib 24 --image-path D:\Images\install.wim --repair-boot true --auto-reboot true

LetRecovery.exe config generate --operation backup --output D:\lr-backup.json --source-partition D: --save-path E:\Backups\data.wim --name Data --format wim --execution-mode direct --output-policy create --auto-reboot false
```

生成器支持 `image-backing-path` 和内置 Administrator 的 `enabled`、`account_name`、`auto_logon`；密码仍严禁作为命令行参数，必须在生成后写入受 protected DACL 保护的配置文件。

## 输出与等待

最终结果写到 stdout 的单个 JSON 对象；执行进度以脱敏 JSON Lines 写到 stderr。安装和备份计划都包含规划器实际采用的 `effective_config`、fresh 库存绑定和 `warnings`，不能只回显输入配置。退出码：`0` 成功、`2` 用法/确认/权限错误、`3` 配置错误、`4` 预检或计划错误、`5` 执行错误。

因为发布物是单一 `/SUBSYSTEM:WINDOWS` EXE，批处理必须显式等待：

```bat
start /wait "" LetRecovery.exe install plan --config D:\lr-install.json
set LR_EXIT=%ERRORLEVEL%
```

PowerShell：

```powershell
$p = Start-Process -FilePath .\LetRecovery.exe -ArgumentList @('install','plan','--config','D:\lr-install.json') -Wait -PassThru -NoNewWindow
$p.ExitCode
```

程序会复用继承的 stdout/stderr；没有有效标准句柄时尝试连接父控制台。不会新增第二个控制台 EXE。
